# gdal.art

Generated GDAL/OGR bindings for Arturo, built entirely on [`arturo-ffi`](https://github.com/Lulzx/arturo-ffi).

The package should not manually mirror GDAL function-by-function. Arturo itself reads the installed GDAL C API, derives the foreign interface, generates Arturo source, records anything it cannot safely bind, and verifies that the generated ABI agrees with the installed GDAL library.

The long-term goal is larger than GDAL:

> Demonstrate that Arturo can mechanically acquire useful interfaces to large real-world C libraries.

GDAL is the first serious stress test after `raylib.art`.

---

## 1. Goal

Produce a usable Arturo interface for the public GDAL/OGR C API with:

- no GDAL-specific native wrapper library;
- no handwritten C glue;
- bindings generated by Arturo;
- `arturo-ffi` as the only generic native FFI transport;
- explicit ownership and lifetime handling;
- deterministic regeneration;
- machine-readable reporting of unsupported declarations;
- runtime ABI verification;
- idiomatic Arturo sugar layered separately over the generated 1:1 API.

The minimum useful result must support both major halves of GDAL:

```text
Raster
  GeoTIFF / DEM / imagery
       ↓
      GDAL

Vector
  GeoJSON / GPKG / Shapefile
       ↓
      OGR
```

OGR is historically the vector component of GDAL. Modern GDAL exposes raster, vector, spatial-reference, algorithms and utility C APIs across headers including `gdal.h`, `ogr_api.h`, `ogr_srs_api.h`, `gdal_alg.h`, and `gdal_utils.h`.

---

# 2. Non-goals

Version 0.1 does **not** attempt to:

- bind the GDAL C++ API;
- provide complete coverage at any cost;
- emulate every GDAL command-line tool manually;
- hide every GDAL concept behind a new abstraction;
- implement GIS algorithms in Arturo;
- silently guess unsupported C declarations;
- translate arbitrary C++ headers;
- support unsafe callbacks merely to improve coverage numbers;
- claim ownership rules that cannot be established;
- replace GDAL's own object/data model.

The generated C API remains available as a relatively direct mapping.

Idiomatic Arturo APIs are an additional layer.

---

# 3. Design principle

`raylib.art` establishes this pipeline:

```text
raylib_api.json
      ↓
Arturo generator
      ↓
generated Arturo
      ↓
arturo-ffi
      ↓
libffi
      ↓
raylib
```

`gdal.art` advances this to:

```text
installed GDAL headers
        ↓
 Arturo C declaration extractor
        ↓
 normalized ABI schema
        ↓
 Arturo binding generator
        ↓
 generated gdal.art
        ↓
    arturo-ffi
        ↓
       libffi
        ↓
      libgdal
```

The important experiment is therefore not:

> Can Arturo call GDAL?

It is:

> Can Arturo derive a large, useful and safe foreign interface directly from a real production C API?

---

# 4. Source of truth

Generated bindings must derive from **installed public GDAL C headers**, not from manually copied declarations.

Initial headers:

```text
gdal_fwd.h
gdal.h
ogr_core.h
ogr_api.h
ogr_srs_api.h
cpl_error.h
cpl_conv.h
cpl_string.h
```

Subsequent coverage:

```text
gdal_alg.h
gdal_utils.h
```

GDAL documents these as public C APIs, while `gdal_fwd.h` contains the forward declarations for GDAL/OGR/OSR handle types.

Do **not** generate from private/internal GDAL headers.

# 6. Generation pipeline

## 6.1 Discover GDAL

The generator must locate GDAL through this order:

1. `GDAL_CONFIG`, if explicitly provided;
2. `gdal-config`;
3. `pkg-config gdal`;
4. standard include/library paths;
5. explicit `GDAL_INCLUDE_PATH` and `GDAL_LIBRARY_PATH`.

`gdal-config`, `pkg-config`, and standard Unix include/library paths do not exist on Windows. On Windows the supported routes are `GDAL_CONFIG` and the explicit `GDAL_INCLUDE_PATH` / `GDAL_LIBRARY_PATH` variables; generation must fail clearly rather than silently searching a nonexistent Unix layout.

`GDAL_CONFIG` is an absolute path to a `gdal-config`-compatible executable (the Windows stand-in for a `PATH` `gdal-config`). Recorded `GDAL_LIBRARY_PATH` / library filename must be passed through to `arturo-ffi` as the `Lib::` prefix, or prepended to `ARTURO_FFI_PATH`.

Record in the generation manifest:

```text
GDAL version
include path
library path
library filename
generator version
arturo-ffi version (Arturo package + adapter_version)
platform
architecture
```

Do **not** write a generation timestamp into `generated/` or any drift-checked file. A timestamp may appear only on stdout / `make coverage`.

Generation must fail clearly if the headers and loaded shared library appear to come from incompatible GDAL installations.

---

## 6.2 Preprocessing

Do not attempt to implement a full C preprocessor in Arturo.

Use the host C preprocessor only as a **source normalizer**, not as a binding generator.

Parse **two views** of the same public headers:

1. Un-preprocessed text of the headers listed in §4 (and `gdal_fwd.h`) for typedef names, opaque handles, enum tags, and source locations. Public GDAL handles are `typedef void *GDALDatasetH` (and the same for band/layer/feature/geometry/SRS). After `cc -E` those names collapse to `void *` and must not be the only type information kept.
2. `cc -E` output, using `gdal-config --cflags` (or `GDAL_CONFIG --cflags`) plus the recorded defines, only for integer constant values and for ABI-layout probes.

Filter discovered symbols to those headers. Preprocessed libc and other transitive declarations are `IGNORED`, not GDAL coverage.

The Arturo generator remains responsible for:

- parsing declarations;
- constructing types;
- determining representability;
- producing signatures;
- generating Arturo;
- building the unsupported report.

The preprocessing command and all relevant defines must be recorded in the generation manifest.

# 7. Intermediate representation

Every extracted API declaration must first become a normalized Arturo value independent of code generation.

Example conceptual representation:

```text
Function [
    name: "GDALGetRasterXSize"
    return: i32
    args: [
        Argument [
            name: "hDataset"
            type: NamedHandle "GDALDatasetH"
        ]
    ]
    source: [
        header: "gdal.h"
        line: ...
    ]
]
```

A function taking a dataset and returning an integer might normalize to:

```text
Function
  name       GDALGetRasterXSize
  return     i32
  args
    hDataset ptr<GDALDataset>
```

The normalized representation becomes the source of truth for:

```text
generated Arturo
coverage report
ABI manifest
ownership annotations
tests
documentation
```

Do not generate Arturo directly while parsing C syntax.

# 8. Required C subset

The declaration parser only needs to understand the subset necessary for the GDAL public C API.

Initially support:

```text
primitive scalar types
typedefs
enums
opaque structs
opaque handle typedefs
pointers
const qualifiers
function declarations
function-pointer typedef recognition
arrays with known dimensions
pointer-to-pointer recognition
simple structs where ABI representation is safe
preprocessor-expanded integer constants
```

Required primitives include at least:

```text
void
char
signed char
unsigned char

short
unsigned short

int
unsigned int

long
unsigned long

long long
unsigned long long

float
double

size_t
ptrdiff_t
intptr_t
uintptr_t
```

Aliases must reduce to an ABI token `arturo-ffi` understands. Never emit `long` or `size_t` as tokens.

| C type | LP64 (macOS/Linux) | LLP64 (Windows x86_64) |
| --- | --- | --- |
| `int` / `unsigned int` | `i32` / `u32` | `i32` / `u32` |
| `long` / `unsigned long` | `i64` / `u64` | `i32` / `u32` |
| `long long` | `i64` | `i64` |
| `size_t` / `uintptr_t` | `u64` | `u64` |
| `ptrdiff_t` / `intptr_t` | `i64` | `i64` |
| pointer / handle | `ptr` | `ptr` |

# 9. Type normalization

Examples:

```text
int
    → i32

unsigned int
    → u32

double
    → f64

const char *
    → str              when semantically input text

void *
    → ptr

GDALDatasetH
    → ptr<GDALDataset>

GDALRasterBandH
    → ptr<GDALRasterBand>

OGRLayerH
    → ptr<OGRLayer>

OGRFeatureH
    → ptr<OGRFeature>

OGRGeometryH
    → ptr<OGRGeometry>

OGRSpatialReferenceH
    → ptr<OGRSpatialReference>
```

Typed handles are an Arturo-level distinction.

At the actual `arturo-ffi` boundary they may all lower to:

```text
ptr
```

but the generator must preserve the semantic type in metadata.

This catches mistakes such as passing:

```text
OGRFeatureH
```

where:

```text
GDALDatasetH
```

is expected.

# 10. Opaque handles

Opaque handles are central to GDAL's C API. GDAL's public forward declarations intentionally expose C handles for underlying GDAL/OGR classes.

Represent them conceptually as:

```text
Handle [
    kind: GDALDataset
    raw: <pointer>
    ownership: owned | borrowed | shared | unknown
    parent: optional handle
]
```

The Arturo API does not necessarily need a custom VM type.

A dictionary or wrapper structure is sufficient initially, provided it cannot accidentally be encoded as another pointer-bearing type without explicit conversion.

Raw generated functions may accept naked pointer values.

The safe/idiomatic layer should prefer typed handles.

---

# 11. Ownership is a first-class part of generation

This is the major difference between generating something that merely calls functions and generating a usable library.

Each pointer/handle result must have an ownership classification:

```text
owned
borrowed
shared
static
caller-buffer
allocated-string
unknown
```

Example conceptual rules:

```text
GDALOpenEx
    return GDALDatasetH
    ownership owned
    destructor GDALClose

OGR_L_GetNextFeature
    return OGRFeatureH
    ownership owned
    destructor OGR_F_Destroy

OGR_F_GetGeometryRef
    return OGRGeometryH
    ownership borrowed
    lifetime parent feature

OGR_L_GetSpatialRef
    return OGRSpatialReferenceH
    ownership borrowed
    lifetime parent layer
```

Ownership information may originate from:

1. an explicit audited metadata table;
2. known naming patterns where unambiguous;
3. GDAL API documentation encoded into a small override database;
4. otherwise `unknown`.

**Never infer ownership solely from naming when ambiguity exists.**

Unknown ownership must not silently become owned or borrowed.

---

# 12. Memory allocators

GDAL/CPL sometimes returns memory that must be released using GDAL's allocator rather than the host allocator.

The binding must expose the relevant CPL release functions.

For example, GDAL documentation specifies cases where returned storage must be freed with `CPLFree()` or `VSIFree()`.

Therefore this is invalid:

```text
GDAL allocation
      ↓
system free()
```

The correct allocator family must remain attached to generated ownership metadata.

Conceptually:

```text
Allocated [
    ptr
    release: cplFree
]
```

---

# 13. `char*` and `char**`

These must not be collapsed into one vague "string" concept.

Classify:

```text
const char *
    input-string

char *
    mutable-buffer | returned-owned-string | returned-borrowed-string

const char * const *
    string-list-input

char **
    output-owned-string | output-string-list | mutable-string-list | unsupported
```

`output-owned-string` is **BOUND** in v0.1. It is the `OGR_G_ExportToWkt` / `OGR_G_ExportToJson` pattern: allocate a `char*` slot, pass its address, read the resulting `char*`, copy the C string, `CPLFree` the pointer. CSL lists remain a later milestone; `GDALOpenEx` v0 may pass `NULL` for the three list arguments.

GDAL heavily uses CSL-style null-terminated string lists.

Support for those is important enough to be an explicit project milestone.

The canonical Arturo encoding of a CSL string list is an ordered block of `"KEY=VALUE"` strings:

```arturo
["COMPRESS=DEFLATE" "TILED=YES"]
```

which converts to GDAL's expected:

```c
char **
```

through safe temporary storage whose lifetime includes the foreign call.

Order is preserved and duplicate keys are legal, so a dictionary is **not** the canonical encoding. The sugar layer may additionally accept a dictionary (or a block of `[key value]` pairs) as ergonomic input and convert it into the canonical block form; the raw generated layer always uses the block.

---

# 14. Output parameters

GDAL makes frequent use of pointer output arguments.

Example shape:

```c
SomeFunction(..., double *x, double *y)
```

Do not expose these only as awkward raw pointers in the high-level API.

The raw generated binding can remain faithful:

```text
rawSomeFunction(... ptr ptr)
```

but generated adapters may return Arturo values:

```arturo
result: someFunction ...
; => [x y]
```

or:

```arturo
#[
    x: ...
    y: ...
]
```

The generator should eventually derive trivial output adapters automatically when:

- the pointer points to one scalar value;
- the pointer is documented/write-only;
- allocation size is statically known.

# 16. Raw generated API

The generated API should remain recognizable to anyone familiar with GDAL C.

For example:

```arturo
ds: gdalOpenEx file flags null null null

width: gdalGetRasterXSize ds
height: gdalGetRasterYSize ds

gdalClose ds
```

OGR:

```arturo
layer: gdalDatasetGetLayerByName ds "buildings"

ogr_L_ResetReading layer

feature: ogr_L_GetNextFeature layer
while [not? null? feature][
    ...
    ogr_F_Destroy feature
    feature: ogr_L_GetNextFeature layer
]
```

A C `NULL` pointer is Arturo `null`, never the integer `0`. `arturo-ffi` returns `ptr` as an integer; generated wrappers (not the raw adapter) must map `0` to `null` before the value is visible to user code. In Arturo, `0` is truthy, so `while [feature: ogr_L_GetNextFeature layer]` would not terminate.

Names should follow the same transformation philosophy as `raylib.art`:

```text
GDALOpenEx
→ gdalOpenEx

GDALGetRasterXSize
→ gdalGetRasterXSize

OGR_G_ExportToWkt
→ ogr_G_ExportToWkt
```

Do not aggressively Arturo-ify acronyms in generated names.

The original C symbol must always be recoverable from generated metadata.

# 20. Raster buffer design

Reading pixels introduces a requirement not exercised deeply by simple function calls:

```text
Arturo storage
    ↕
raw contiguous memory
    ↕
GDALRasterIO
```

This belongs in **arturo-ffi** (`../arturo-ffi` in the sibling checkout), not in GDAL-specific C glue. Required adapter primitives (version ≥ 3), all additive to the existing text `adapter_call` protocol:

```text
adapter_alloc(n) → ptr          ; one integer argument
adapter_free(ptr)
adapter_load_cstr(ptr) → string|null
adapter_mem(op, args)           ; two strings, same shape as adapter_call

`adapter_mem` ops: `u8`/`u8=` … `i64`/`i64=`, `f32`/`f32=`, `f64`/`f64=`, `ptr`/`ptr=`, `memset`, `copy`. Arguments are `ptr;offset[;value]` decimal text. Arturo `call.external` only reliably forwards the first integer argument, so multi-scalar memory ops must not be extra integer parameters.
```

Required Arturo operations those implement:

```text
allocate N native bytes
obtain pointer
pass pointer through FFI
read/write scalars and C strings
release allocation
```

Do not encode raster payloads as `adapter_call` argument text. Decode pixels from the native buffer in Arturo (typed loads). Large RasterIO may still walk the buffer in Arturo; that is allowed. Pathological is shipping each pixel as a protocol token.

Minimum `arturo-ffi` for gdal.art v0.1 is adapter version 3. Pin that version in the generation manifest.

**Regression gate:** after every `arturo-ffi` change, `make test` in `../arturo-ffi`, then sync or bump the `arturo-ffi` submodule in `../raylib.art` and run `make native && make test` there (`make gen` first if `arturo-ffi/main.art` changed, because raylib inlines it). New symbols must be additive; existing `ffiCall` / struct / color paths must keep the same ABI.

`gdal.art` can then add datatype-aware decoding:

```text
GDT_Byte
→ Arturo integers

GDT_Float32
→ Arturo floating values
```

Do not encode large raster data through the textual argument protocol one pixel at a time.

# 26. Unsupported declarations

Every public declaration encountered by the generator must end up in exactly one state:

```text
BOUND      generated and intended to be called
DEFERRED   representable later; reason required
IGNORED    seen but not a bindable GDAL/OGR/CPL function
           (macros-only, non-GDAL includes, non-functions)
```

Never silently disappear. The §40 report uses these three names only.

Example:

```text
BOUND       812
DEFERRED     47
IGNORED      19
TOTAL       878
```

Deferred report:

```text
symbol                          reason
-------------------------------------------------------
foo                             callback argument
bar                             variadic
baz                             unsupported ptr***
quux                            unknown ownership
...
```

The report is generated every time.

Equivalent Arturo value:

```arturo
gdalDeferred: #[
    "SomeFunction": "callback argument"
    "OtherFunction": "unsupported pointer depth"
]
```

# 27. Deferred features

Initially defer rather than fake support for:

```text
variadic functions
callbacks
function-pointer arguments
complex unions
unknown-size arrays
unsafe pointer arithmetic
triple-pointer constructs without semantics
opaque value structs requiring unknown ABI behavior
functions whose ownership cannot be safely expressed
```

Later implementation is allowed only when the capability belongs generically in `arturo-ffi`.

That rule is important:

> If GDAL requires a new foreign-function capability, improve `arturo-ffi`; do not hide the problem in a GDAL-specific C wrapper.

---

# 28. ABI verification

Generated bindings must be verified against actual compiled C.

For all supported primitive and struct layouts verify, where applicable:

```text
sizeof
alignment
field offsets
enum values
```

Opaque handles only require pointer-width compatibility.

The generator should emit a tiny temporary C verification program containing compile-time or runtime probes such as:

```text
sizeof(type)
offsetof(type, field)
constant values
```

Arturo compiles and executes this program during `make check`.

The probe exists only for verification.

It must not become a runtime wrapper library.

---

# 29. Symbol verification

For every generated function:

```text
generated declaration
        ↓
shared-library symbol lookup
        ↓
present?
```

Record missing symbols.

Account for functions that may vary by GDAL version.

Bindings must include version guards where needed rather than assuming every function exists everywhere.

# 30. Version model

`gdal.art` targets an explicit minimum GDAL version.

Minimum supported version:

```text
GDAL >= 3.8
```

Generation should use the **installed version's headers**, allowing newer APIs automatically when representable. Features or functions introduced after the installed version are simply absent from that build's generated output; they are reported, not assumed. Because the floor is already at or above GDAL 3, all supported GDAL installations use the GDAL 3 default CRS axis semantics (see §24).

Manifest example:

```json
{
  "gdal_version": "3.x.y",
  "generator_version": "...",
  "functions_seen": 0,
  "functions_bound": 0,
  "functions_deferred": 0
}
```

Do not claim one fixed function count in perpetuity.

# 31. Deterministic generation

Running:

```bash
make generate
```

twice against the same:

```text
GDAL version
headers
generator commit
platform ABI
```

must produce byte-identical generated Arturo sources (`generated/*.art` and the drift-checked subset of `generated/manifest.json`). Manifest fields that vary per run (if any) are excluded from the comparison.

`make check` is two independent steps:

```text
1. generate twice into temporary directories; fail if the two trees differ
2. if GDAL_CHECK_VERSION matches the installed GDAL
      (default pin: 3.8.x, the documented golden version)
      compare against checked-in generated files and fail on drift
   else
      skip the golden comparison (still run generate + tests)
```

CI jobs on “current stable” GDAL therefore do not fail `make check` solely because newer headers added functions. Same determinism philosophy as `raylib.art`, without pretending one golden tree fits every GDAL.

# 37. Error handling

GDAL maintains an error system through CPL.

Expose enough error state that Arturo can produce useful diagnostics:

```text
error class
error number
message
```

A failed operation should be representable as something richer than:

```text
null
```

Sugar may translate:

```text
NULL result + CPL error state
```

into:

```arturo
error "GDALOpenEx: ... "
```

Raw bindings remain raw.

Pointer results that are C `NULL` become Arturo `null` in the generated layer (see §16).

# 38. Lifetime tests

Ownership bugs are among the highest-risk aspects of the project.

Tests must deliberately cover:

```text
owned dataset closed exactly once
owned feature destroyed exactly once
borrowed geometry never destroyed independently
borrowed layer remains valid while parent dataset lives
borrowed geometry invalid after parent feature destruction
CPL-owned string released with CPLFree
temporary char** remains alive for duration of call
```

Where possible run tests under:

```text
AddressSanitizer
LeakSanitizer
Valgrind
```

depending on platform.

# 49. Hard constraints

These rules are non-negotiable.

### No handwritten GDAL C wrappers

If a call cannot pass through generic `arturo-ffi`, defer it or improve `arturo-ffi`.

### No silent omissions

Every public declaration receives a disposition.

### No unsafe ownership guesses

Unknown means unknown.

### No generated-file editing

Fix the generator and regenerate.

### No C++ API

Use the public C API.

### No fake portability

Run CI against multiple platforms and GDAL installations before claiming portability.

### Improve `arturo-ffi`, then re-check `raylib.art`

If GDAL needs a new foreign-function capability, add it to the sibling `../arturo-ffi` package. After every adapter or `main.art` change: `make test` in `arturo-ffi`; bump or sync the submodule in `../raylib.art`; `make native` and `make test` there (`make gen` first when `arturo-ffi/main.art` changed). New entry points must be additive.

# 54. Definition of v0.1

`gdal.art` v0.1 exists when all of the following are true:

- Arturo parses/preprocesses public GDAL C declarations.
- Bindings are generated rather than handwritten.
- Generated functions call through `arturo-ffi`.
- No GDAL-specific native wrapper exists.
- GDAL version is detected and recorded (minimum GDAL 3.8, per §30).
- A GeoTIFF can be opened.
- Raster dimensions and band count can be read.
- A raster band can be read into Arturo.
- A GeoJSON or GeoPackage can be opened.
- OGR layers can be enumerated.
- Features can be iterated.
- Fields can be read.
- Geometry can be exported to WKT.
- Owned features and datasets are released correctly.
- Unsupported declarations are enumerated with reasons.
- Regeneration is deterministic.
- `make check` detects generated-source drift.
- ABI checks pass.
- Tests pass on macOS arm64 and Linux x86_64.

# 56. Research question

This project should preserve one explicit question:

> **How much of a complex production C ecosystem can Arturo bind mechanically from declarations alone before semantic information, rather than ABI information, becomes the limiting factor?**

`raylib.art` mostly tests ABI generation from unusually friendly structured metadata.

GDAL adds the difficult pieces:

```text
headers
typedef chains
opaque handles
pointer-heavy interfaces
output parameters
ownership
foreign allocators
null-terminated string lists
large buffers
version-dependent APIs
interconnected subsystems
```

That makes failures valuable.

Every deferred function should answer *why* mechanical generation stopped.

The result is therefore both a practical geospatial package and a benchmark for Arturo as a language capable of constructing its own foreign interfaces.

The strongest demonstration is:

```bash
git clone --recursive ...
```

followed by:
